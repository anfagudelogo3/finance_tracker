# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A WhatsApp-based personal finance tracker: Twilio delivers inbound WhatsApp messages to an AWS Lambda Function URL, the Lambda parses them with OpenAI (text / vision / Whisper), stores structured expenses in Neon PostgreSQL, and replies over Twilio. User-facing strings are Spanish; code and comments are English.

**Tech stack:** Python 3.12, `uv` for dependency management. Key libraries: `openai` (SDK), `twilio` 9.10.4, `psycopg2-binary` 2.9.11, `boto3`, `openpyxl`, `requests` — see `pyproject.toml` for declared ranges and `uv.lock` for exact resolved versions.

`build/` and `lambda.zip` are deploy artifacts regenerated by `scripts/deploy.py` — never edit them; `build/finance_tracker/` is an installed copy of `src/finance_tracker/`.

## Architecture

Single Lambda, one entry point, straight-line pipeline. `lambda/handler.py` (copied to the zip root, so the Lambda handler setting stays `handler.handler`) re-exports `finance_tracker.handler.handler`. `src/finance_tracker/handler.py::_handle_message` runs the whole request in order: parse form body → `webhook.verify_signature` (401 on failure) → `webhook.extract_message` → allowlist check on `ALLOWED_PHONE_NUMBERS` → `get_or_create_user` → `database.save_message` → `load_recent_turns` / `save_turn` → `media.store_all_media` (S3) → intent routing → reply.

**Intent routing** — first match wins:
1. `fast_paths.is_excel_request` — keyword match → build `.xlsx`, upload to S3, send presigned link
2. `fast_paths.fast_route(...) == "reporting"` — the narrowed report fast path → `orchestrator.handle_message` → `agents.reporting`
3. Image → `legacy.openai_parser.parse_expense_from_image` (OpenAI vision, not yet migrated)
4. Text / audio (audio → Whisper `transcribe_audio` first) → `orchestrator.handle_message`: `fast_paths.fast_route` picks `agents.expenses` / `incomes` / `reporting` for free when the intent is unambiguous; everything else goes to `routing/router_agent.py` (Claude Haiku 5.5), which delegates to one or more agents as tools, asks a clarifying question, or declines

**Hybrid routing rules:** `fast_route` only fires for `personal` profiles, never when the last assistant turn was a question, and never on multi-intent or suspicious text; it must never be wrong on `evals/datasets/route_message.json` (enforced by `tests/routing/test_fast_paths.py`). The router's reply is assembled in code from the specialists' `reply_text`s — the router never writes amounts itself. Its loop (`core/agent_loop.py`) stops on `stop_reason == "end_turn"`; `ROUTER_MAX_ITERATIONS` and `AGENT_LOOP_TIMEOUT_SECONDS` are safeguards only. Design: `docs/agent-roadmap.md` §4.

Because Excel is checked first, "exportame el resumen" is an Excel request, not a report.

**Error contract:** the body of `_handle_message` is wrapped in `try/except`; any unhandled error logs, sends `MSG_ERROR` in Spanish, and still returns `200` so Twilio does not retry. Preserve this — new failure modes should surface as a friendly reply, not an exception.

**Idempotency:** `save_message` uses `ON CONFLICT (whatsapp_message_id) DO NOTHING` and returns `None` on a duplicate; the handler short-circuits with `200`. Twilio retries are therefore safe.

**Dates:** `America/Bogota` (`zoneinfo`) everywhere — the agents (and `legacy.openai_parser`) stamp the record date, the handler passes `now` into `parse_report_request`. Do not fall back to naive `datetime.now()`.

### Package layout (`src/finance_tracker/`)

| Path | Responsibility |
|------|----------------|
| `handler.py` | Lambda handler, pipeline orchestration, branch selection |
| `config.py` | All env vars and tunable constants (models, cutoffs, reply strings) |
| `core/` | Shared contracts and helpers: `agent_types.py` (`AgentRequest`/`AgentResponse`), `agent_loop.py` (tool-use loop), `claude_client.py`, `confidence.py`, `text.py` |
| `routing/` | `fast_paths.py` (all keyword checks + `fast_route`), `orchestrator.py` (fast path, else router), `router_agent.py` (Claude router, agents as tools) |
| `agents/` | Specialists, each `handle(AgentRequest) -> AgentResponse`: `expenses.py`, `incomes.py`, `reporting.py` (+ `report_format.py`) |
| `channels/whatsapp/` | `webhook.py` (Twilio HMAC verification, payload → message dict), `sender.py` (outbound messages/documents, confirmation formatting) |
| `storage/` | `database.py` (psycopg2), `media.py` (Twilio media → S3 `incoming/whatsapp/{prefix}/{phone}/{sid}.{ext}`), `excel.py` (`.xlsx` + presigned URLs) |
| `legacy/` | `openai_parser.py`: OpenAI paths not yet migrated (image vision, Excel date parsing, original text parser) plus Whisper transcription (permanent) |
| `observability/` | `tracing.py`: optional Phoenix/OTel setup; no-op unless `PHOENIX_TRACING=1` |

New agents go in `agents/`, new routing logic in `routing/`, new external integrations in their own module under the matching subpackage (a new channel → `channels/<name>/`). Read env vars / constants only in `config.py`. Tests mirror this tree under `tests/` (test basenames must stay unique — the test folders have no `__init__.py`).

**Confidence heuristic:** `core/confidence.estimate_confidence` is a 0–1 field-completeness score (0.5 for a valid `amount`, 0.3 for a non-`otro` `category`, 0.2 for a non-empty `description`) — not a model-reported probability. It's attached to every parsed expense, persisted in `expenses.confidence`, and logged in `handler.py`, but nothing currently branches on its value (no low-confidence retry or flagging) — treat it as informational/for later analysis, not a gate.

**Cost awareness:** every inbound message triggers a live OpenAI call (text, vision, or Whisper transcription), each billed and adding latency. Don't swap models, add extra LLM calls, or call the LLM speculatively without flagging the cost/latency tradeoff.

## Hard constraints

**Absolute package imports.** All code lives in the `finance_tracker` package (`src/finance_tracker/`) and imports absolutely: `from finance_tracker.storage.database import ...`. Never use a `src.` prefix, bare-name imports (`from config import ...`), or relative imports. `scripts/deploy.py` installs the package into `build/` via `uv pip install .` (hatchling, see `pyproject.toml`) and copies `lambda/handler.py` to the zip root. Keep subpackage `__init__.py` files empty — importing a subpackage must not import its modules (that would break the tracing order and config bootstrap below).

**`config.py` reads `os.environ` at module scope** and will `KeyError` on import if any of the nine required vars are missing: `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_WHATSAPP_NUMBER`, `ALLOWED_PHONE_NUMBERS`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `DATABASE_URL`, `S3_BUCKET_NAME`, `WEBHOOK_URL`. Both test and eval entry points work around this by seeding placeholders *before* the first `src` import — `tests/conftest.py` and `evals/__init__.py`. Any new import path into `finance_tracker` needs the same bootstrap.

**Webhook signature verification is security-critical.** `webhook.verify_signature` is what proves an inbound request actually came from Twilio (HMAC over `WEBHOOK_URL` + params using `TWILIO_AUTH_TOKEN`); the handler rejects with `401` on failure. Never weaken, bypass, or disable this check — including temporarily, including to make a failing test pass. Fix the test or the call site instead.

**`tracing.setup_tracing()` must run before `legacy.openai_parser` or any agent is imported** (see the ordering at the top of `handler.py` and `evals/run.py`) — the OpenAI/Anthropic instrumentors patch the client classes, so the client singletons must be created after it.

**The `evals` dependency group must never reach the Lambda.** `scripts/deploy.py` uses `uv pip install .`, which installs base deps only; `tracing.py` returns early when Phoenix env vars are absent so production is unaffected.

## Evals

`evals/scoring.py` is pure Python (no network) and is unit-tested by `tests/test_eval_scoring.py`. `evals/run.py` loads JSON datasets from `evals/datasets/`, calls the real parser, and prints per-field accuracy plus failures.

Scoring only checks fields present in a dataset entry's `expected` block — omitting a field means "don't care", and `"payment_method": null` asserts the model invents nothing. Thresholds live in `THRESHOLDS` in `evals/run.py` (`amount` is the strict one at 95%).

Evaluated today: the legacy `parse_expense` / `parse_report_request`, the Claude extraction in `agents/expenses.py`, `agents/incomes.py`, `agents/reporting.py` (date resolution), and routing (`route_message.json`, keyword baseline only until the Phase 5 router exists). Image and audio paths aren't evaluated yet. When you change a prompt in `agents/` or `legacy/openai_parser.py`, run `uv run python -m evals.run --check`.

## Schema

`scripts/setup_db.sql` is idempotent (`CREATE TABLE IF NOT EXISTS` + `ADD COLUMN IF NOT EXISTS` migrations at the bottom). Adding a column means: append an `ALTER TABLE ... IF NOT EXISTS` there, update `database.py`, and update `docs/database.md`.

`users` → `messages` (whatsapp_message_id UNIQUE) → `expenses` / `incomes`; plus `conversation_turns`, `categories`, `budgets`. Full schema in `docs/database.md`.

**Preferences are append-only:** `user_prefs` gets a new row (full snapshot + changed keys + `created_at`) on every change and is never UPDATEd; every read takes the user's latest row (`database.get_user_prefs`). Write only through `database.append_user_prefs`. `users.prefs` is deprecated and not read.
