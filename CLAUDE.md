# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A WhatsApp-based personal finance tracker: Twilio delivers inbound WhatsApp messages to an AWS Lambda Function URL, the Lambda parses them with OpenAI (text / vision / Whisper), stores structured expenses in Neon PostgreSQL, and replies over Twilio. User-facing strings are Spanish; code and comments are English.

**Tech stack:** Python 3.12, `uv` for dependency management. Key libraries: `openai` (SDK), `twilio` 9.10.4, `psycopg2-binary` 2.9.11, `boto3`, `openpyxl`, `requests` — see `pyproject.toml` for declared ranges and `uv.lock` for exact resolved versions.

## Commands

```bash
uv sync                                    # install runtime + dev deps
uv sync --group evals                      # add Phoenix/OpenInference (eval-only group)

uv run pytest tests/                       # full unit suite (all externals mocked, no creds needed)
uv run pytest tests/test_parser.py -v      # single file
uv run pytest tests/test_parser.py::test_name   # single test

uv run python -m evals.run                 # LLM evals — makes LIVE OpenAI calls, needs a real key
uv run python -m evals.run --check         # exit 1 if any metric is under threshold (CI gate)
uv run --group evals python scripts/start_phoenix.py   # trace UI at localhost:6006

./scripts/deploy.sh                        # build lambda.zip (rewrites build/ and lambda.zip)
aws lambda update-function-code --function-name finance-tracker --zip-file fileb://lambda.zip
```

`build/` and `lambda.zip` are deploy artifacts regenerated by `deploy.sh` — never edit them; `build/*.py` are stale copies of `src/*.py`.

## Architecture

Single Lambda, one entry point, straight-line pipeline. `src/handler.py::_handle_message` runs the whole request in order: parse form body → `webhook.verify_signature` (401 on failure) → `webhook.extract_message` → allowlist check on `ALLOWED_PHONE_NUMBERS` → `database.save_message` → `media.store_all_media` (S3) → intent routing → reply.

**Intent routing** — exactly one of three branches, first match wins:
1. `parser.is_excel_request` — keyword match → build `.xlsx`, upload to S3, send presigned link
2. `parser.is_report_request` — exact substring match, then `difflib` fuzzy word match at cutoff `0.8` → in-chat summary
3. Expense (default) — routed by message type: audio → `transcribe_audio` + `parse_expense`, image → `parse_expense_from_image`, text → `parse_expense`

Because Excel is checked first, "exportame el resumen" is an Excel request, not a report.

**Error contract:** the body of `_handle_message` is wrapped in `try/except`; any unhandled error logs, sends `MSG_ERROR` in Spanish, and still returns `200` so Twilio does not retry. Preserve this — new failure modes should surface as a friendly reply, not an exception.

**Idempotency:** `save_message` uses `ON CONFLICT (whatsapp_message_id) DO NOTHING` and returns `None` on a duplicate; the handler short-circuits with `200`. Twilio retries are therefore safe.

**Dates:** `America/Bogota` (`zoneinfo`) everywhere — `parser` stamps `expense_date`, the handler passes `now` into `parse_report_request`. Do not fall back to naive `datetime.now()`.

### Module responsibilities (`src/`)

| Module | Responsibility |
|--------|----------------|
| `handler.py` | Lambda entry point, pipeline orchestration, intent routing |
| `webhook.py` | Twilio HMAC signature verification, payload → message dict |
| `parser.py` | All OpenAI calls, intent keyword matching, confidence heuristic (see below) |
| `database.py` | psycopg2 queries on `messages` + `expenses` |
| `media.py` | Twilio media download → S3 (`incoming/whatsapp/{prefix}/{phone}/{sid}.{ext}`) |
| `excel.py` | `.xlsx` generation + presigned S3 URLs |
| `reporting.py` | In-chat summary formatting, grouped by currency and category |
| `whatsapp.py` | Outbound Twilio messages/documents |
| `config.py` | All env vars and tunable constants (models, cutoffs, reply strings) |
| `tracing.py` | Optional Phoenix/OTel setup; no-op unless `PHOENIX_TRACING=1` |

Add new external integrations as their own module, and read env vars / constants only in `config.py`.

**Confidence heuristic:** `parser._estimate_confidence` is a 0–1 field-completeness score (0.5 for a valid `amount`, 0.3 for a non-`otro` `category`, 0.2 for a non-empty `description`) — not a model-reported probability. It's attached to every parsed expense, persisted in `expenses.confidence`, and logged in `handler.py`, but nothing currently branches on its value (no low-confidence retry or flagging) — treat it as informational/for later analysis, not a gate.

**Cost awareness:** every inbound message triggers a live OpenAI call (text, vision, or Whisper transcription), each billed and adding latency. Don't swap models, add extra LLM calls, or call the LLM speculatively without flagging the cost/latency tradeoff.

## Hard constraints

**Flat imports.** Modules import each other by bare name (`from config import ...`, `from parser import ...`) because `deploy.sh` copies `src/*.py` to the root of the Lambda package. Never introduce a `src.` prefix or subpackages under `src/` — the Lambda runtime won't resolve them.

**`config.py` reads `os.environ` at module scope** and will `KeyError` on import if any of the nine required vars are missing: `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_WHATSAPP_NUMBER`, `ALLOWED_PHONE_NUMBERS`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `DATABASE_URL`, `S3_BUCKET_NAME`, `WEBHOOK_URL`. Both test and eval entry points work around this by seeding placeholders *before* the first `src` import — `tests/conftest.py` and `evals/__init__.py`. Any new import path into `src` needs the same bootstrap.

**Webhook signature verification is security-critical.** `webhook.verify_signature` is what proves an inbound request actually came from Twilio (HMAC over `WEBHOOK_URL` + params using `TWILIO_AUTH_TOKEN`); the handler rejects with `401` on failure. Never weaken, bypass, or disable this check — including temporarily, including to make a failing test pass. Fix the test or the call site instead.

**`tracing.setup_tracing()` must run before `parser` is imported** (see the ordering at the top of `handler.py` and `evals/run.py`) — the OpenAI instrumentor patches the class, so the `OpenAI()` client instance must be created after it.

**The `evals` dependency group must never reach the Lambda.** `deploy.sh` uses `uv pip install .`, which installs base deps only; `tracing.py` returns early when Phoenix env vars are absent so production is unaffected.

## Evals

`evals/scoring.py` is pure Python (no network) and is unit-tested by `tests/test_eval_scoring.py`. `evals/run.py` loads JSON datasets from `evals/datasets/`, calls the real parser, and prints per-field accuracy plus failures.

Scoring only checks fields present in a dataset entry's `expected` block — omitting a field means "don't care", and `"payment_method": null` asserts the model invents nothing. Thresholds live in `THRESHOLDS` in `evals/run.py` (`amount` is the strict one at 95%).

Only `parse_expense` and `parse_report_request` are evaluated; image and audio paths are planned phases. When you change a prompt in `parser.py`, run `uv run python -m evals.run --check`.

## Schema

`scripts/setup_db.sql` is idempotent (`CREATE TABLE IF NOT EXISTS` + `ADD COLUMN IF NOT EXISTS` migrations at the bottom). Adding a column means: append an `ALTER TABLE ... IF NOT EXISTS` there, update `database.py`, and update `docs/database.md`.

`messages` (id, whatsapp_message_id UNIQUE, phone_number, raw_text, transcript, created_at) → `expenses` (message_id FK, amount, currency, category, expense_date, payment_method, merchant, description, confidence, source, created_at).
